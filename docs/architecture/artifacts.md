# 产物格式：一份富信息 JSON + 按需导出 + 可编辑的字幕稿

**这是产物侧的现行契约**（2026-09-09 落地；字幕稿 2026-09-27 加，script-fx 计划）。需求怎么来的、实现过程中四轮复审揪出什么，
在 output-format-plan（已归档的计划书）。

- **机器侧**的一级产物只有一份 `<tag>-tracks.json`（匹配产物同理），别的格式都由阶段 3 从它投影；
- **人工编辑层**是阶段 3 写的[字幕稿](#5-字幕稿阶段-3-写阶段-4-读)（`*.script.ass`）：在 Aegisub 里改，阶段 4 只读它、不回读阶段 2。

工具：`flowocr.artifacts.tracksio`（形状 + 读写校验）、`flowocr.output.export`（投影出 SRT）、
`flowocr.output.script`（投影出字幕稿）、`flowocr.typeset`（阶段 4：字幕稿 → 最终叠加 ASS）；入口是 `render` 的预设和 `flowocr.typeset`。

## 1. 一级产物只有一份

`build_tracks` 写 **`<tag>-tracks.json`**，它是机器侧唯一的事实来源：

```text
schema / tag / meta / frame_us / size / window_sec / n_windows
provenance : git_head, argv, args, main_track, main_srt, main_cues, main_candidates,
             matcher?（建轨给了 --matcher 时：spec、patch、overridden、ctx = --matcher-ctx；其中的 game 在同一个匹配器匹配时继承）,
             viewport?（建轨给了 --viewport 时：游戏画面在录像里的 [x, y, w, h] 像素；建轨不用，匹配时没给 --ctx viewport= 就用它对版式文件，不分匹配器）
regions[]  : index, label, lang, primary_score, n_windows_present, features,
             align?（left / center / right）, align_how?（by = stats / vote / none、n、spread、votes）
tracks[]   : id("r00" / "main" / "np"), kind, region|regions, label, srt, ui_lines[], cues[]
             cues[] : id, t_start, t_end, events[]（事件 id，**顺序就是导出时的行序**：先分行、行从上往下、行内从左到右）,
                      hide[]?（这条 cue 里投影时不给的成员：同句合并留下的半截行和杂行）, partial[]?（hide 里的半截行，全部文字的视图也不给）, panel_like?
events[]   : id, region, t_start, t_full, t_end, box, text, conf, n_obs,
             n_independent, flags[], boxes[]?（只有 moving 的才落）, texts[]?（可选）,
             t_full_sampled?（采样级全字出现）, t_full_how?（回抠填：首字 / 全字各是 agree / single / none；全字只防晚很多：没有两路同意且比最早候选晚 10 帧以上时夹回、记 capped）,
             t_full_end?（回抠填：完全显示结束）, t_end_how?（t_end 来自 curve 字形对比度 / ncc 整框相关系数；open = 测量窗里一直没看到它消失——字到窗尾还在屏上或视频先结束——t_end 只是下界、不填 t_full_end；moving = 末段还在平移（弹幕、滚动评论、拖动中的地图），结尾窗只盯最后那一格框、给的终点早于采样级，不认它，t_end 留采样级、不填 t_full_end；下游按采样级的终点用，阶段 3 另有两处：含它的条目和 open 一样不做淡出，认重读时它的终点多容一个采样间隔，[defaults.md 1.65](defaults.md#165-回抠覆盖全部区域文字效果只从正文区域统计2026-10-24)）
text_effect? : 回抠写的整段素材效果统计：samples, verdict?（instant / typewriter / likely-typewriter；样本 < 8 不写）,
             ms_per_char_median?, iqr_over_median?, fade_out_*?
```

* **`align` 是区域的对齐方式**（2026-09-24，overlay-style 计划）：
  `flowocr.analyze.align` 在 `build_tracks` 落盘前判——区域统计（左沿 / 中心 / 右沿哪个最稳）判不出时，
  由同屏上下相邻的两行成对投票；叠加导出只照着锚边。**可选字段**：旧产物没有它，不读对齐的下游照常能读；
  叠加预设读到没有它的产物当场报错、提示重跑 build_tracks（只是阶段 2）。

* **`kind` 有三种**（2026-09-20 加了第三种）：
  * `region` —— 一个区域一条，**下游遍历 tracks 时只该认这一种**（见下面第 4 条契约）；
  * `main` —— 并带之后的聚合投影，装的是区域轨里已经有的同一段文字；
  * **`nameplate`** —— 打了 `nameplate` 标的 run 的投影（`<tag>-nameplate.srt`，id 固定 `np`）。
    判据是 `flowocr.analyze.uigate.pick_nameplates`（框位 + 在正文带上方 + 时长 ≥ 台词 + 词表小，
    **按时间分窗**；ui-gate 计划）。
    ⚠ **它和区域轨有意重叠**：同一条 run 两边都在——用途 1 要在原位看到名牌，
    用途 2 要把它并进正文（`merge_nameplate --paste`）。
* **事件的 `flags`**：`moving` / `scrolling`；`clipped_start` / `clipped_end`——自选范围（`--regions`）的时间关闭段截断的起止，不是字自然出现或消失：
  回抠不找这一端的自然边界、也不量到范围外的时段（`refine_boundaries`），常驻 UI 的时间占比不再给截短的 run 补一格（`uigate`）；
  `ui_filtered` / `ui_footprint` / `nameplate` 是打标不删（下面第 2 条契约）。切点来自 obs 的 `_meta.regions`（组的规格原样记下，加切点秒数 `boundaries`），`build_tracks` 从这里重建时间关闭段。
* **`-provenance.json` 并进去了**，不做兼容；`clear_stale_srts()` 会把旧的那份
  连同 `<tag>-main.srt` / `<tag>-nameplate.srt` 一起删掉（它们都是"某个开关打开时才产"的文件，
  关掉之后旧的留在原地最危险）。
* 旧格式的产物 `tracksio.load` **当场拒收**（"schema 不是 `flowocr-tracks/1`"）——
  响，不是静默降级。`out/` 里 47 个历史 A/B 臂**故意**留在旧格式：文档里的数出自它们。
* 下游取值走 `python -m flowocr.artifacts.tracksio <tracks.json> main_srt`，**别自己 `json.load`**
* **匹配产物 `*-matched.json` 同理**：格式、版本和"匹配上用原文否则留 OCR"的规矩只有一份，在
  `flowocr.artifacts.matchedio`（2026-09-22）；从它出字幕走阶段 3 的入口
  `python -m flowocr.output.render <matched.json> --preset matched_srt|default|default_all|dev`，
  **各层盖哪些块已经在阶段 2 判好写进 `overlay.items`，预设只投影、不重新判断**（同第 1 条）；同样别自己 `json.load`（那样校验就丢了）。
  叠加条目的时间：`extra` 取它自己那几个事件的时段；`body` 取记录的起止（分段时取那一段 cue 的），但起点被同一条 cue 里别的字
  （名牌、计数器、按键提示、还没消失的上一句）拉早超过 1.5 个采样间隔时，挪到这句字在正文位置上出现的时刻
  （正文事件，或同一处和正文或剧本原文同一句的变体、打字刚出的几个字，`scriptmatch.body_start`）；终点夹到这句字最晚的消失
  （正文事件，或同一处同一句、整个包住正文的读数，`scriptmatch.body_end`，[1.50](defaults.md#150-叠加正文的终点夹到这句字消失2026-10-10检测器三场修复计划)）。
  定起点时借来的那些读数（不在正文事件里的同一句变体、打字半截）记进这条 `body` 的 `events`、排在正文事件后面，别的认领自己的正文事件不借；定终点时认的不记（[1.66](defaults.md#166-正文块定起点借来的读数记进它的事件2026-10-24-owner-定)）：
  块盖住了它们，选项层、`unmatched` 补画都不再用，名牌层也让出（被认成开头行的借来读数不另画名牌块），打字机也看得见这句字早就在屏。记录本身（`cues[]`）的起止不动，
  `matched_srt` 出记录时起止取这条记录正文条目的（没有正文条目的照记录）。
  匹配器声明了推荐预设（`PRESET` / `PRESET_OPTS`）时，`flowocr.analyze.match` 把它写进 `provenance.recommend`（`{preset, opts, by}`），
  `render` 不给 `--preset` 时照用：推荐跟着产物走，渲染时不必再加载匹配器。
* **认领方式 `how`**（`cues[]` 的每条记录）：`exact`（cue 的某种读法和剧本行逐字相同）/ `fuzzy`（相似度过 `--fuzzy`；`gametext` 的打字机半截、读到一大段这两种补漏认领也记 `fuzzy`）/
  `contain`（`gametext`：剧本行整行落在 cue 里，只靠这种认上）/ `context`（本句的字不够认、靠上下文认上的：`naninovel` 是本句相似度不到门、靠往后几条 cue 的后文；
  `gametext` 是夹缝认领——cue 夹在同一单元上下两行的认领之间、读法是中间那行的一截，[defaults.md 1.67](defaults.md#167-第五遍认领短句夹在同一单元相邻两行的认领之间2026-10-24-owner-定方向)）/ `none`（没认上，`ref` 为空）。
  `ref.score` 一律是读法和剧本行诚实的相似度，`contain`、`context` 的分可以很低（`でも` 对 `でも…` 0.57），所以 `gametext` 产物的可疑改写（`stats.suspect`）不数这两种。
* **显示协议**（`flowocr-matched/6` 起，owner 2026-10-07）：画哪些由匹配器在产物里声明，所有吃匹配产物的预设（叠加三个、`script`、
  `default_srt`、`matched_srt`、走 `script.build_items` 的用户预设）按同一条规则过滤（`matchedio.visible`，校验在 `matchedio._check_display`）：
  * 顶层 `display = {"groups": {组名: {"tier": "always" | "on" | "off", "label": 给人看的名字}}, "fill": {"tier": "on" | "off"}}`。
    `always` 直接进默认、关不掉；`on` 默认进、`hide` 关得掉；`off` 默认不进、`show` 打得开。组名由匹配器起；
    `unmatched`、`unfed` 是每个匹配器都要声明的**保留组**，`all`、`fill` 是选项关键字、不能当组名。
  * 每次认领（`cues[].ref`、`cues[].extra[]`）和每个叠加条目（`overlay.items[]`）带 `group`（声明过、不是保留组）和 `fill`（布尔：
    认领了、但 OCR 没读到这句，即**填位**）；`body` / `extra` 条目的这两个值和它 `claim` 指向的认领相同。`ref` 为空的记录不带，它归 `unmatched`。
    组挂在认领上、不挂在记录上：一条记录可以同时装台词和选项按钮。填位是认领的标记、不是组——填位的选项仍在选项那一组。
  * `overlay.fed`：喂给匹配器的 cue 用到的事件 id（升序）。两个保留组的内容**不写进产物**，画的时候按它推（`matchedio.fed_rest`）：
    `unmatched` 是 `fed` 里没被任何叠加条目引用的事件（`cues[]` 里是 `ref` 为空的记录），`unfed` 是 tracks 里不在 `fed`、也没被引用的事件。
  * **画不画**：组可见，且不是填位、或填位可见。默认可见 = `always` + `on` 的组，填位按 `display.fill`；`--opt show=a,b` / `hide=c` 增减，`show=all` 打开全部组加填位。
    叠加条目另要有所选语种的文本才画；`layer` 只定**怎么画**（盖在正文行上、独立的块、名牌、称号、阅读面板），不定画不画。
    `unmatched` 可见时，可见、但没有所选语种文本的条目退回画它事件的 OCR 原文；阅读面板画出来时，两个保留组的事件扣掉被它盖住的那段时间。
    `matched_srt` 只出主认领：`ref` 可见才出，有所选语种的文本出剧本文本，没有的、以及 `ref` 为空的记录只在 `unmatched` 可见时出 OCR 原文；`ref` 的组是 `special` 的一律不出（下面一条）。
  * **名牌的两个组**（`flowocr-matched/7`，owner 2026-11-05，两个内置匹配器都声明，`matchedio.NAME_GROUPS`）：名牌块逐块看，在屏时正下方有一块认上的台词
    （组 `dialogue`、不是对话记录面板里的旧行；同一块名牌前后几次出现有一次挂上就都算）的留在 `name`（默认画），没有的归 `stray_name`（默认不画：队伍栏、好友列表、头顶名字、对话记录面板里的字）。
    挂上的名牌里，叠在另一块名牌下面（或上面）、字小一号的是称号，层是 `title`（字幕稿用 `Title` 样式）；`stray_name` 打开时字幕稿用 `StrayName` 样式。只改组和层、不改译文
    （[defaults.md 1.72](defaults.md#172-名牌逐块看挂没挂在认上的台词上称号单列2026-11-05-owner-定)）。
  * **名牌的译名从哪来**（`name_src`，两个内置匹配器的名牌条目都带，`scriptmatch.py` 写）：按这个顺序查，先查到的算——
    `speakers`（屏上的字对上剧本说话人表）→ `terms`（对上短名词表：按字形查，查到的是游戏自己的译法，但那块字不一定是人名；所以只在这块字主要挂在台词上（比例到 `TERM_ON_DIALOGUE`）时才用，挡掉的块数记在 `overlay.stats.name_terms_off`）→
    `voted`（逐字都查不到时，按名牌下面那几句台词的说话人投票，`fuzzy_names`）→ `fuzzy`（没有充分的投票时，借这段视频里已译出、只差一个字的名牌）；都没有是 `null`，这块名牌没有译文。
    `overlay.stats` 的 `name_from_terms` / `name_from_voted` / `name_from_fuzzy` 是各种来源的名牌事件数。
  * **特殊上屏形式的组**（owner 2026-11-07，`matchedio.SPECIAL`）：组名 `special` 是共享层认的名字，不只管画不画——字幕稿里这一组的条目不论哪一层都用 `Special` 样式（阶段 4 按正文行排），
    `default_srt`、`matched_srt` 两个 SRT 预设和走 `script.srt_blocks` 的用户预设都不出（`default_srt` 和用户预设按样式排除，`matched_srt` 按 `ref` 的组排除），`show=special` / `show=all` 也不出，`matched_srt` 也不退回出 OCR 原文。
    游戏文本包匹配器把原神语音字幕里 style 不是 `Normal` 的行和绝区零散条目的 `Tips` / `MiddleTips` 归这一组（默认画）；自己写的匹配器只在要这套画法时才用这个组名（[defaults.md 1.74](defaults.md#174-特殊上屏形式的台词与提示单独一组默认画2026-11-07-owner-定)）。
  * **名牌字色**（`flowocr-matched/7` 之内加的可选字段，2026-11-05）：游戏文本包匹配器给 `name` 组里有译名的名牌量原文字色（`analyze.nameink`），
    判过的条目带 `ink`（`true`：和这款游戏的名牌色对得上；`false`：对不上，字幕稿用 `PlainName` 样式、白字），`overlay.name_ink` 记这款游戏各层的名牌色
    （`{"name": "#rrggbb", "title": …}`，阶段 3 写进 `Name` / `Title` 样式）。没判的（没有这款游戏的名牌色、找不到源视频、naninovel）两样都没有，读的一方当白字（[defaults.md 1.73](defaults.md#173-名牌照游戏的名牌色画特例不上色2026-11-05-owner-定)）。
  * 匹配产物上没有 `keep` / `layers` 选项（传了报错）；`keep` 只留给 tracks 产物。回显去重（下一条）是 SRT 拍平的规则、不是可见性，叠在可见性之后。
* **回显判定**（`flowocr-matched/4`，2026-10-06）：同一句剧本行（变体组并到代表行）被认领了几次时定一次"主"，其余标出它是什么。
  `cues[]` 的每条记录和它的每条 `extra` 都带两个字段：`echo` 是 `same_time` / `log` / `replay` / `other` 之一（主和只认领一次的是 `null`），
  `echo_of` 是主那次认领 `[记录下标, slot]`（slot −1 是那条记录的 `ref`，≥0 是它的第几条 `extra`；主是 `null`）。记录上的这对字段说的是它的主认领 `ref`，`extra` 的写在 `extra` 自己身上；
  `overlay.items` 的 `body` / `extra` 条目带 `claim`（它是哪次认领，`[记录下标, slot]`）和那次认领的 `echo` / `echo_of`。
  SRT 一类预设（`matched_srt`、`default_srt`，以及走 `script.srt_blocks` 的用户预设）默认不出 `same_time` / `log`，`--opt echo=keep` 放回来；叠加预设和字幕稿照画。
  只在**主那次认领确实出进这份 SRT** 时才去：`matched_srt`（一条记录一条 cue、只出 `ref`）在主是某条记录的 `ref` 时才去（`matchedio.record_kept`），
  `default_srt` 在主那次认领有叠加条目要出时才去（`script.srt_blocks`；`extra` 的事件全被主认领占了时没有叠加条目）。
  主落在 `extra` 上时 `matched_srt` 会把这一句别处所有 `same_time` / `log` 都照出，偏离一句一条（四场整场没出现过）。
  `stats.repeat_extra_band_echo`（`naninovel` 是 `repeat_extra_echo`）是多出来的认领按这四种拆开的计数，几格之和等于 `repeat_extra_band`（`repeat_extra`）。
  判定是匹配器之后、导出之前的一遍（`flowocr.analyze.echo`，内置两个匹配器共用），**不改认领本身**：
  * 同一行的认领按时段聚成"出现"：时段重叠或相隔 ≤ 2 s 的算同一次，不分区域；
  * 主在**离剧本锚点时刻最近的那次出现**里（锚点是 `gamescript.sequence` 的排序时刻，即这一行在 obs 里第一次被检索到的时刻、不分区域，
    所以实际几乎总等于最早那次出现，只有最早那次没进 obs 检索时才不同；认不出的对话记录先于正文上屏时主会落在对话记录上。顺序剧本的 `naninovel` 没有锚点，取最早那次）；
    那次出现里几处认领时，在主轨上的 > 不是面板样的 > 分数高的 > 早的；
  * 主那次出现里另一区域的 → `same_time`；别的出现里按顺序：cue 面板样 → `log`；和主同一区域 → `replay`（真实重演）；
    另一区域、这一刻（±1 s）各区域一共认领了 ≥ 2 条别的旧行（比它第一次被认领晚 10 s 以上）→ `log`；
    其余（含同一次出现里和主同一区域、`merge_runs` 没并上的那一截）→ `other`，报警留给人看。
* **原文整块与文本框画像**（`flowocr-matched/8`，2026-11-10，两个内置匹配器都写，`analyze.textbox`）：叠加的正文译文按它分行、摆行、定字号（见[导出](#4-导出)的分行、摆行、字号三条），
  这几样要剧本在手才判得出，所以由匹配器判、写进产物；阶段 3 出叠加时缺了就报错要求重跑匹配，`/7` 的产物整个拒收。
  * `overlay.textbox`：区域号（字符串）→ `{valign, pitch, em, chars, box_w, align, h_inertia, evidence, latin_em?}`，按这一份产物（一段视频）、按区域估；
    `latin_em` 只从版式文件来（英文一个拉丁字平均占几个 `em`，日文录像量不出），阶段 3 / 4 画英文译文时按它定字号、折行。
    `valign` 是文本框的竖直对齐 `top` / `bottom` / `center`：按原文整块的行数分组，看首行下沿、末行下沿、首末两行下沿的中点哪个不随行数变（按下沿量，Ruby 会把上沿撑高），
    判不出（不到两种行数、或三种都不稳）是 `top`；`pitch` 是行距（相邻两行下沿之差的中位，px）；`em` 是原文一个全角字多宽（行宽对行里字宽之和的回归斜率，检测框外扩的常数项不算，px）；
    `chars` 是一行能放几个全角字：只拿游戏**被宽度逼出来的自动折行**当证据（剧本同一行落在两个 OCR 行上、断点前后是两个能断开的全角字、不是空格和标点），
    每条证据给一个区间 [lo, hi]（lo 是被折那一截的宽，hi 再加下一截首字的宽；字体是比例字，hi 取闭），取让最多条证据成立的值（候选只取各条的 lo，并列取大的），几条离群证据不会把它拉高；一段视频里不到 2 条证据、或者取出的值下成立的不到证据的一半（证据不是同一个框宽折出来的，次要区域常见）就是 `null`（不折）；`box_w` 是文本框宽：有 `chars` 时是 `chars × em`；没有、折行证据又不到 2 条时（游戏几乎不自动折行、超框时缩字号的，如《魔裁》），整行读全的行里不同的剧本行到 2000 句就取最宽那行的字格宽加半个 `em`（句少时最宽那行离框沿还远），不够是 `null`；
    `align` 是横向对齐 `left` / `right` / `center`：只拿整行读全的 OCR 行（对上剧本一整行），行首全角左括号、行尾全角句读点 / 右括号往外补半个 `em` 换成字格边，
    比左沿、右沿、中心的离散（MAD，以 `em` 计），最小的不超过 0.25、又小于次好的一半就是它，这时 `h_inertia`（横向吸不吸）为真；整行读全的行不到 5 个、分不开，或者判出居中而多行条目块里各行左沿齐、中心不齐（整块居中、行左对齐的旁白和提示气泡，两种对齐都画不对）时，取建轨判的 `regions[].align`、不吸。
    阶段 3 摆正文 / extra 译文按它对齐（建轨判的只在没有画像时用）；画像只从正文行量，同一区域的选项、offmain、名牌照旧按 `regions[].align`；`evidence` 是折行证据的条数。量不出的是 `null`。
    **版式文件兜底**（短片段样本不够）：匹配器选中的游戏有[版式文件](#1-一级产物只有一份)（`--ctx layout=<文件>` 换一份、`none` 不用）时，先定游戏画面在录像里的位置（视口，见版式文件一条），
    区域中心换到视口里离文件里某一条纵向不超过 0.08 个视口高、横向不超过 0.08 个视口宽，量出了 `em` 的再要 `em / 视口高` 相差不超过 10%，区域自己整行读全的行宽过那条框宽加半个 `em` 的不超过 5%（至少 2 行才算超）、折行证据在那条的 `chars` 下成立的不少于一半，就用那一条**补量不出的**：`em`（`em_h` × 视口高）、`pitch`、判不出的 `valign`、`chars`、`box_w`、对齐（只在整行读全的行不到 5 个时补，补了就横向吸附），长度按 `em` 换算；量得出的照旧用现量的。
  * `body` / `extra` 条目的 `block`：原文整块，这句日文在屏上每一行的框 `[x0, y0, x1, y1]`，按日文剧本的行号从上到下排；剧本的一行被游戏折成几行时占几个框。
    收进条目的 OCR 行按文字对到剧本第几行，再按位置核（量出区域行距之后，和其余行推出的首行下沿差半个行距以上的不收，同一句读了两遍的留位置对得上的那个）；没收进来的行先在同一条 cue 里找真实事件（缺的首行常被认成名牌），找不到按行距合成，横向取真实几行合起来的范围；
    剧本只有一行的条目整块就是 OCR 行。`block_src` 和 `block` 等长，每行的来源 `ocr` / `event:<事件 id>` / `synth`；
    `block_drawn_by` 也等长，来源事件被别的叠加条目画着（多是名牌）时记那个条目在 `overlay.items` 里的下标，否则 `null`。
    被借的事件是名牌层的块、它的下沿又离同一区域前后各 10 块名牌的下沿中位差半个正文行距以上的，是台词首行被认成了名牌：那块名牌去掉、这一行记 `null`（`scriptmatch.yield_to_block`）。
    **条目的 `rows` 不动**：名牌分组拿正文 `rows` 的首行判名牌挂没挂在台词上，补出的首行常常就是那个名牌事件。
  * 整块建好之后过一次**惯性**：参照是同一区域、时间上前后各 10 条正文 / extra 条目的真实行（合成的不算）；每个真实行的下沿按 `valign` 换算成整块的锚再取中位，
    条目自己的锚和参照差不到半个行高就是同一版式，整块每一行的下沿放到参照的位置（行距取参照条目的中位）；差得多的当成另一种版式、用自己的框；参照不到 3 条也用自己的框。
    吸过去会把某个真实行的下沿挪半个行高以上的（锚对得上、行距不同的版式）也当成另一种版式。
    同一版式、`h_inertia` 的区域，每一行按参照真实行的对齐边横向吸附（左对齐取左沿的 p20、右对齐取右沿的 p80、居中取中心的中位；开头是括号、省略号，或 OCR 漏读了开头的行也吸）；吸附只放宽、不收窄：对齐边只往参照外侧挪（左对齐左沿取原左沿和参照中靠左的，右沿不小于参照；右对齐对称；居中按参照中心对称放到盖住原框），吸附后的框总盖住原框。
    惯性之后，量出了 `em` 的区域每一行再**按字数放宽**：期望宽 = 这一屏行该显示的日文（OCR 行对上的那一截，剧本的一行只落在一个 OCR 行上时是整行；补出的行是剧本那一行）的墨迹宽 × `em`，墨迹宽是字宽和减去行首左括号、行尾句读点 / 右括号字形里空着的半格；从对齐边往外放到不小于它，只放宽、不收窄，窄不到半个 `em` 的、日文宽过 `chars` 的、区域有折行证据、`chars` 却是 null 时期望宽超过本区域 OCR 行宽 p99 半个 `em` 以上的（游戏会把它折开）不放。`block` 是吸附、放宽之后的框。
  * `overlay.stats.textbox` 是诊断：各区域的条目数、`valign` 的分组和三种锚的极差、折行证据逐条（下界、上界、剧本行）、`chars` 下成立 / 不成立的条数，整块各来源的行数，
    没进整块的 OCR 行数（整块按剧本行建时对不上剧本行、或位置对不上的），缺首行的条目数和补上的条数，补的行被别的条目画着的行数，被整块借成首行、去掉的名牌块数（`names_yielded`），各区域的对齐打分（`align`：建轨判的对齐、判据来源 `by` = `rows` / `tracks` / `inner_left`、整行读全的行数 `n` 和左 / 右 / 中三种离散）和文本框宽的来源（`box_w`：`by` = `chars` / `rows` / `none`、行数 `n`），各区域从版式文件补了哪些字段（`layout`：`entry` / `fields`，对上了位置却和区域的行对不上的记 `rejected`）、用的版式文件（顶层 `layout`：`source` / `sha`）、
    游戏画面（顶层 `viewport`：`by` = `ctx`（给定的：匹配的 `--ctx viewport=` 或建轨记下的 `provenance.viewport`）/ `frame`（整个画面对上了）/ `inferred` / `fallback`（没对上、也反推不出，退回整个画面），`box` = 录像里的 `[x, y, w, h]` 像素，反推的另记配它的 `region`、`entry` 和对上的台词条数 `items`；没有版式文件是 `null`），各区域惯性的同一版式 / 另一种版式（其中按行判出的）/ 参照不够 / 挪了的条数和竖直、横向位移的分布，按字数放宽的行数（按来源分）和放宽量的分布。
  * **真记录面板**（`gametext` 匹配器认的，`scriptmatch.log_panels`：面板样，本句上下几行有别的旧台词；它的 cue 不和别的 cue 并成一条记录）：
    一句有不是真记录面板的认领时，真记录面板的认领**不参与**聚成出现、不参与定主，一律 `log`——哪怕和台词框那次只隔不到 2 s；
    一句的认领全是真记录面板时照上面的规则。`naninovel` 不认真记录面板，判定照上面（[defaults.md 1.51](defaults.md#151-对话记录面板不并进台词框的记录记录里的同一句判-log2026-10-10-owner-定方向检测器三场修复计划)）。
* **占位**（`{NICKNAME}` 这类花括号，2026-10-05）：剧本里运行时才定的值（玩家起的名字、流浪者的名字、运行时取值）。
  原神按性别取的称谓（`{PLAYERAVATAR#SEXPRO[…]}`）不算：文本包带称谓表时，阶段 2 按投出的主角性别直接换成文字（性别写法 `{M#…}{F#…}` 同理）。
  阶段 2 **不删**：剧本行的 `cn` 和 `jp_tpl`（日文原文模板，有占位时才有；`jp` 照旧是删了占位、匹配用的原文）里原样留着，
  顶层可选的 `fills` 是匹配器猜的值：`{占位: {"value": 值或 null, "by_lang": {"jp": …, "cn": …, "en"?: …}, "how": 从哪来, …}}`
  （各语种相同的名字记 `value`；各语种不同的记 `by_lang`，输出哪种语言取哪个）。共享层只认花括号，猜值是匹配器特化的，游戏文本包匹配器猜两种：
  ①**星铁 `{TEXTJOIN#n}`**（玩家给宠物、飞船、社团起的名字，游戏给几个候选、有的能自定义）：剧本带着这些 n 的候选（`textjoins`，文本包有候选表时），
  按模板锚点从 OCR 原文截出名字，按分隔号切段后和候选比相似度（≥ 0.75 且明显胜过第二名才算；像某个候选又不够像的不投，离所有候选都远才算玩家自定义的名字），
  截不出就在整句里逐字找候选（剧本固定文字里本来就有的不算）；整部片投票、严格过半采用（候选按 cue 1 票就够，自定义的名字按剧本行要 ≥ 2 票），认不出用默认项；
  ②玩家起的名字 `{NICKNAME}`（三款游戏同一个写法），两个来源一起投票、得票 ≥ 2 且过半才采用——
  认上的剧本行原文模板里有这个占位的，拿占位前后的字去 OCR 原文里找夹在中间的名字（所有游戏）；**只给原神**：认上主角自己说的台词时，
  那条 cue 里建轨打了 `nameplate` 标记的事件的文字（owner 2026-10-05：按版式认名牌有过拟合之嫌，限在原神）。
  gi1 / gi2 整场：ねるめろ(本物) 5/5、ぴくと 27/28 票。阶段 3 把占位标出来、阶段 4 填值（[字幕稿](#5-字幕稿阶段-3-写阶段-4-读)的占位一条）；
  SRT 没有阶段 4，标记留在正文里由人改。**自己读 `cn` / `jp_tpl` 出字幕的下游要处理花括号**（`flowocr.placeholders`）。
* **英文译文**（2026-11-10，可选字段，剧本是 `flowocr-gameref/7`、匹配产物没升版本）：游戏文本包有英文那份时，剧本行另带 `en` / `en_rich` / `speaker_en`、

  英文只是载荷：圈单元、认领、名牌投票都照旧只看日文和中文，名牌认出是谁以后按日文名查英文名。`en_rich` 不带注音（原神的英文注音标在单个拉丁字母上）。
  阅读面板有一段没对上英文（英文那份的段数和日文不同）的整块不带 `paras.en`。
  阶段 3 的 `lang` 取 `jp` / `cn` / `en`，产物里一条这个语种的文本都没有时报错（不静默退回 OCR 原文；`cn` 同样，以前是悄悄只画 OCR 原文）；Naninovel 剧本没有英文。
* **样式**（2026-10-23，[defaults.md 1.62](defaults.md#162-剧本的行内样式带进字幕styleon2026-10-23-owner-定)）：剧本里的粗体、斜体、下划线、删除线、字色。

  成对、按层嵌套，`flowocr.richtext`），和不带样式的那份只差标签，不同时才有；匹配只看不带样式的。可选字段，剧本和匹配产物都没升版本。
  阶段 3 按 `style` 选项（默认 `on`）取带样式的那份：纯文字照旧量宽、断行，写正文时按"非空白的字逐个对上"把标签投回各行，
  字幕稿写成 ASS 行内标签（闭标签回到外层的状态，最外层是空的 `\1c`）；SRT 是基础输出、不带（owner 2026-10-23）；阅读面板不带。
  游戏的 Unity 富文本里字号（绝对像素，要按游戏定基准才能换算）、对齐（一段里某几行右对齐，ASS 的对齐是整条一个）和别的标签不带。
  **Ruby**（2026-10-23，[defaults.md 1.63](defaults.md#163-剧本的-ruby写进字幕稿阶段-4-画在正文上方rubyon2026-10-23-owner-定)）：正文上方的小字（日文多是读音，中文多是语义注释）存在同一个字段里，

  各来源先换成同一种写法：原神 `{RUBY#[D]读音}` / `{RUBY#[S]读音}` 标的是读音的中心点、不是范围，换成中心相同的最小范围（`[D]` 是标记两边各一个字、`[S]` 是标记前一个字；
  `[D]` 右边没字当 `[S]`、左边没字只包右边那个，`[S]` 左边没字丢掉）；星铁 `{RUBY_B#读音}正文{RUBY_E#}`、绝区零 `<ruby><rt>读音</rt>正文</ruby>` 和 `<ruby=读音>`、Naninovel `<ruby="读音">` 照范围。

* **剧本与游戏文本包（`gtd-bundle/1` 的消费端）**：对白层只依赖剧本，匹配不要求文本包在手边；阅读面板层（`--opt readables=1`）例外，匹配时读包里的 `readables` 表，按"包指纹 + 模块代码指纹"缓存，记在 `overlay.stats.panel_gametext`。
  剧本缓存键 = 游戏 + 产剧本的代码指纹 + 包的内容指纹，不用文件 mtime（拷贝 / 解压会改 mtime、让缓存白白失效，mtime 相同而内容不同时又会误命中）；命中时仍核包里用到的文件的存储哈希。
  剧本的 `provenance` 带 `gametext` 块（游戏、指纹、`rev`、版本、上游、提取器、是否核过完整性、来源包名——不记绝对路径），逐项见 `gtdbundle.Bundle.provenance`，剧本格式的版本史见 `gamescript.SCHEMA` 的注释；包本身的规格在 game-text-data 那边（release 计划）。

* **版式文件（`flowocr-layout/2`，匹配器读）**：一款游戏一份，随代码走的在 `flowocr/analyze/layouts/<游戏>.json`（文件名是匹配器认的游戏名），也可以 `--ctx layout=<文件>` 给自己的。
  由 `dev_tools/layout_export.py` 从整场的匹配产物导出，只取条目多、量出了一字宽的区域，几份产物里位置和字号相近的并成一条，每个字段只取那份产物自己量出的。
  位置和长度都按**游戏画面**（视口）量，和录像怎么摆游戏画面无关：主播布局把游戏缩在一角、加黑边、游戏长宽比不同，同一个对话框的这几个数不变。
  顶层 `schema`（必填）、`game`、`aspect`（导出时游戏画面的宽 / 高，必填）、`boxes`；`boxes[]` 每条：`id`、`dx`（区域中心离游戏画面中心的横向距离 / 游戏画面高，左负右正，必填）、
  `cy`（离游戏画面顶 / 游戏画面高，必填）、`em_h`（一字宽 / 游戏画面高，必填）、
  `pitch_em`（行距 / 一字宽）、`box_em`（文本框宽 / 一字宽）、`chars`（一行几个全角字，整数）、`valign`、`align`（只在源产物判得出时有）、
  `latin_em`（英文一个拉丁字平均占几个一字宽：日文录像量不出，按这款游戏英文版录像手填，导出时中心相近的条目原样带过来）、`sources`（来源区域，诊断）。
  横向按「离中心、以高为单位」量：游戏界面一般按高缩放、对话框居中摆，游戏画面变宽变窄时这个距离不变。
  匹配器读文件时就核这些字段（`cy` 在 0–1、`dx` 是有限的数、长度和 `aspect` 是正数、`valign` / `align` 取画像的取值），不合规报错、点出条目和字段，不写出匹配产物；`schema` 不是 `flowocr-layout/2` 的文件报错。
  **游戏画面在录像里的位置**（视口，`textbox.locate`）按这个顺序定：给了就用它（录像像素 `x,y,w,h`：匹配的 `--ctx viewport=`，没给时建轨 `--viewport` 记在轨道产物里的；出了录像画面报错）；
  否则按 `aspect` 放进录像、居中（16:9 录像就是整个画面），有区域对得上条目就用它；一个都对不上时，拿每个量出了一字宽的区域配每一条，按「这个区域就是这一条」反推（高 = `em / em_h`，位置由中心和 `dx` / `cy` 定），
  要纵向落在录像里、中心横向在录像里、高不小于录像高的四分之一，配它的区域还要和条目的行对得上，几个都行取对得上的台词最多的；都不行按整个画面（对不上就不补，记 `fallback`）。
  导出按匹配产物记的视口换算：反推出来的（那是拿旧文件配出来的）、`fallback` 的（游戏画面多半不占满录像）不收，主播布局这类录像要给了游戏画面位置（建轨 `--viewport` 或匹配 `--ctx viewport=`）重跑匹配再导出。
  改了画像的量法（`fit_em`、`fit_chars`、`box_width` 这类）要重新导出，没有东西会检查文件过时。
## 2. 四条契约

1. **切分、常驻 UI 的判定、并带的结果都已经写在 JSON 里**，导出器只做**投影**。
   回抠在建轨末尾结算之后也走同一个导出器重出 SRT，所以 audit-4 C6（当年回抠 CLI 的 `--srt-only` 绕过输出过滤）在结构上不可能再发生。
   **⚠ 保持关注**（2026-09-14）：用途 2 的叠加 ASS（`scriptmatch --ass`）里"主轨外的选项按钮 / 阅读面板 / 名牌该不该盖"
   原先在导出时现场判；现在判定写进 `*-matched.json` 的 `overlay.items`，导出只按层投影（matcher 计划）。
   但**规则本身**是按预览摆帧长出来的（`choice_items`）、`readable_items` 的段从文本包的 `readables` 表来（选开，产物 `provenance.params.readables` 记开没开；它按帧只读一遍 obs，依赖 obs 行按 `t_us` 非递减——`run_ocr2` 就这么写，乱序会当场报错）、名牌判据会认进键位和 UI——
   owner 要求对这块持续关注（产品方向记录）。
2. **过滤不删事件、只打标**：事件带 `ui_filtered`（文本那条判据，**逐轨**）/ **`ui_footprint`**（框位 + 时间占比那条，**全局**）/ **`nameplate`**。⚠ **两种 UI 判决的作用域不同，别混成一个 flag**——混了导出器会把『区域轨里判的 UI』带进主轨（实测 592 → 541，守卫当场抓到）。文本那条的权威清单是**逐轨**的
   `tracks[].ui_lines`（同一行在区域轨里够比例、并进主轨后不一定够）。
   用途 1 要留、用途 2 要剔，同一份数据。
   另有 **`ruby`**（振り仮名：紧贴含汉字正文上方、字高约一半、全假名，**全局**、按几何）：它不是 UI，是正文的注音，
   和 UI 一样只打标：剔 UI 的导出（`cue_lines` 默认、SRT、匹配器、`default` 叠加）不给，全部文字的视图（`drop_filtered=False`、`dev` / `default_all` 叠加）照给、按 UI 标——
   判据是几何的、会误标，误标的字要读得回来（2026-09-26，[defaults.md 1.30](defaults.md#130-建轨的四项2026-09-26)）。
   框位 UI 和注音在切 cue **之前**就和正文分开：区域轨里它们自成 cue，并带主轨里不收。
   非区域轨（并带主轨、名牌轨）只装区域轨 cue 里已有的事件（`tracksio.validate` 每次 `load` 都核）：切分会按上下文筛行
   （`--srt-mode body` 的去重、各模式丢碎段），同一条 run 在自己的区域里被筛掉的，并带之后的切分里留下来也拿掉（`build_tracks.within_regions`）。
   **"事件在不在主轨上"按事件判**（`tracksio.in_main`）：所在区域在并带主轨的 `regions` 里，或事件带 `band_merged` 标。
   `regions` 只列**整块**并进主轨的区域；实验开关 `--main-band-unit window` 只从某些区域并进一部分事件，这些区域不列进 `regions`，并进来的事件靠 `band_merged` 认。
   下游（选项层、阶段 3 的主轨标）别按区域判，用 `in_main`。默认路径上打了 `band_merged` 的事件区域都在 `regions` 里，两种判法结果相同。
3. **下游遍历 `tracks` 要用白名单 `kind == "region"`，不是黑名单**（2026-09-20 的真回归）：
   `scriptmatch.feed_from_doc` 原来只排 `kind == "main"`，名牌轨一加就被**喂了第二遍**，
   而且是"独立成条"的形式——`methodology-audit-3` 记过代价：只有名字的 cue 会去抢
   含名字的剧本行，**重复认领涨 2.2~7.0 倍**。守卫 `t_panel_like` 里钉了
   "加一条名牌轨，三种 `--feed` 的条数都不变"。
4. **`t_full` 没回抠时是 `null`，不许拿 `t_start` 顶替**（打字机三态）；
   `boxes[]` 只给 `moving` 的事件；`n_independent` 全是沿用票时**就是 0**。

## 3. 回抠只更新时间

`refine_boundaries` 就地改事件的 `t_start / t_full / t_end`，然后
`tracksio.refresh_cue_bounds(doc, before)` 把 cue 的边界跟着挪——**切分一个字不动**。
`before` 是回抠前的快照（`event_times()`），没有它就一个边界都不动。

三条规矩（每条都是一次复审换来的，`refresh_cue_bounds` 的 docstring 里有反例）：

| 规矩 | 不这么做会怎样 |
| --- | --- |
| 一条 cue 的边界**只认它自己的成员**（起点取最早、终点取最晚） | 别的轨、别的 cue 里碰巧同一时刻开始/结束的事件会把它拽走 |
| **有成员跨过切点**才算共享、才一起挪（不是"时间相接"） | 相接但独立的两条被绑在一起，后一条会在**空白期提前显示** |
| 夹只夹这一条自己（首尾不倒挂），**不跨 cue 夹单调** | `raw`/`cue` 档的 cue 本来就能时间重叠，跨 cue 夹会把后一条硬推到前一条的终点上 |

**起点口径（`first` / `full`）是导出时的投影，不写进 JSON**（`export.cue_start`）——
写回去之后那个值不再等于任何事件的首字时间，就再也切不回 `first` 了。

## 4. 导出

```powershell
python -m flowocr.output.export <tracks.json>                        # 逐轨 SRT（与 build 写的逐字节相同）
python -m flowocr.output.render <tracks.json> --outdir tmp\ov        # 叠加：默认预设 default（只留主轨），写字幕稿 + 最终 ASS
python -m flowocr.output.render <tracks.json> --preset dev --outdir tmp\ov   # 开发看：全部区域、聚类编号
python -m flowocr.output.render <tracks.json> --preset script --opt keep=all --outdir tmp\ov   # 只写字幕稿
python -m flowocr.typeset tmp\ov\<tag>-all.script.ass [--preset dev]  # 改完字幕稿再生成最终 ASS
```

`render` 不覆盖已有的字幕稿：同名的已在就报错退出、一个文件都不写（字幕稿是人改的那一层，owner 2026-11-11），`--force` 才覆盖；直接调 `script.render_script` / 预设的库调用（驱动、`preview.py`）照写，开关是 `script.OVERWRITE`。

**叠加字幕**（把字压回原位，overlay-style 计划；2026-09-27 起分成字幕稿和特效两步，script-fx 计划）：
tracks 产物叠 OCR 原文，matched 产物叠剧本译文，走同一个投影核心 `flowocr.output.script`，写成[字幕稿](#5-字幕稿阶段-3-写阶段-4-读)；
阶段 4（`flowocr.typeset`）读字幕稿生成最终 ASS。三个叠加预设两步连跑、两份都留下：

| 预设 | 保留（tracks / matched） | 样式 |
| --- | --- | --- |
| `default`（`render` 的默认） | 主轨 + 名牌轨 / 匹配器声明的默认可见组（显示协议） | 底板近黑、α 0x20；`plate_color=on` 时取画面背景色（见下） |
| `default_all` | 全部区域轨，常驻 UI 照常画 / `show=all`：全部组加填位，`unmatched` / `unfed` 的事件照 tracks 画 OCR 原文 | 同 `default` |
| `dev` | 同上，UI 黄字（#ffe033）；字幕稿另写效果判定的依据 | 非主轨浅蓝（#73d7ff）、底板内侧右上角红字（#ff2d2d）区域号、底板 α 0x80 |

* **取事件按轨取**：`default` 走主轨的 `cue_lines`（和阶段 2 的主轨 SRT 同一个行集），全部区域时按**那条区域轨自己的**
  `ui_lines` + 全局的 `ui_footprint` + cue 上藏的杂行标 UI——不用事件上的 `ui_filtered`（第 2 条契约）。
* **一句一条**（2026-10-05，cue-shape 计划）：一条 cue 的正文行（`tracksio.cue_rows`：分行、同一行相隔不远的几段拼成一行）写成一条 Dialogue，行间 `\N`；
  起止是这些行和它们的半截行的最早起点 / 最晚终点，夹在 cue 里。照旧一事件一条的：名牌、UI、在动的、在这条轨上挂在几条 cue 里的
  （按句画会叠好几层）、终点和这一句多数行差 0.1 s 以上的（一条 Dialogue 只有一个终点）、和后续隔开了的半截行（真单独显示过的一段）。**一个事件只画一次**。
  matched 的 `unmatched` / `unfed` 组可见时补画的 OCR 原文照旧一事件一条（认领按事件算）；正文条目原文整块从 cue 里借来的事件（`block_src` 是 `event:<id>`、`block_drawn_by` 是 `null` 的）在那个条目的底板下，不补画。
* **对齐**：锚哪条边看区域的 `align`，matched 的正文 / extra 条目看文本框画像的 `align`（`overlay.textbox`，没有画像时同别的层）（在动的事件——有 `boxes[]`——一律居中，不看 `align`：框跟着字走；区域统计也只用不动的事件）；原文锚这一行自己的框，译文锚整组的公共轴（正文译文只按原文整块里真实的框算，见下面的摆行一条）。
* **效果检出即开**：打字机逐字显出（按事件判：被回抠过的看全字出现离首字 ≥ 2 个原生帧，整段判"字确实没有生长"时不做；
  没被回抠的看 `t_full_sampled` ≥ 2 个采样间隔）；有 `t_full_end` 就复刻淡出（成员里有 `t_end_how` 是 `open` / `moving` 的不做）；淡入最长 300 ms。在动的、名牌、选项不做。
  门的细节和依据见 [defaults.md](defaults.md) 的叠加 ASS 一节。判定在阶段 3 做一次，写进字幕稿（`\fad`、`fo` 的 `tw`）。
  `--opt typewriter=dim` 是审计时刻用的两态（全字出现前半透明）。
* **打字机行的底板跟着字长**（owner 2026-10-05）：只盖原文已出现的部分 ∪ 译文已显出的部分（`plate=text` 只算译文，`plate=src` 只算原文），一个字都没出现时不画，
  全字出现后是两者的并集。原文按字幕稿 `fo` 的 `grow`（每行首字 → 全字）从左沿匀速长、领先一个行高；译文按逐字显出的时刻跳。
  逐行摆的 `rows` 在原文、译文靠右的那个左沿处切成两块，拼起来正好是并集、不重叠；正文译文行数和原文整块不同时底板是拼起来的横条，每条按盖着它的那几段（译文行、原文行、读音）长；`box` 和整块画的行盖已出现部分的外接矩形。
  画法是静态底板加一个随时间变的 `\clip`（`\t` 插值）。在动的、人挪过位置的、不做打字机的行照旧是静态底板。
* **底板取画面背景色**（阶段 4 的 `plate_color=on`，默认关、要手动打开；2026-10-22，owner 2026-10-31 改成默认关）：阶段 4 生成完所有行之后读源视频，把近黑底板换成颜色取自画面的不透明小格，盖住原文、看不出是一块（`flowocr.typeset.platecolor`）。
  每块底板按 5 fps 取样（每行头尾各 0.15 s 不取，剩下不到一个采样间隔的很短的行取离中点最近的那个取样帧，最多差 0.1 s、视频结尾前的最多差 0.2 s，可能在行的显示区间外）：底板外扩 12 px 的取样带里找出笔画（底板外的笔画也抹，免得把旁边的 ▼、头发抹进底板），同一时刻别的底板整块抹掉，在 1/3 分辨率上 inpaint 补出背景；取样带没被抹的不到一成就加宽（12 → 24 → 48 px，加宽后不退回）。
  底板切成约 24 px × 半行高的小格，格色沿时间中位滤波、按折线简化写成 `\t` 关键帧，相近的格并成一块，格间重叠 3 px、`\blur3`；打字机的 `\clip` 链每格只留扫过它的那几步。小格用专门的样式 `P.fo-fx`（无描边、无阴影、左上对齐；源样式里已有叫 `P` 的就换成 `P1.fo-fx`……），省掉逐条重复的 tag。
  正文按底板中位色的亮度写深色字（L > 62）或白字，描边换成底板色；人在行首写的颜色 tag 在后面，照旧压过它；样式的主色被人改过（不再是字幕稿默认的白）的，这个样式的正文不自动改色。取色时底板不透明，`plate_alpha` 不起作用。
  只动阶段 4 自己画的底板和正文（生成时就知道哪行是什么，不按长相认）：扩展效果画的框、区域号原样留着。
  只解码有底板的时段（各块的取样区间并起来，隔不到 2 s 的连成一段）；有 N 卡先试 NVDEC（丢帧、缩放在显存里做，下传后和软解走同一条转色路径，解出的帧逐字节相同），开不了就软解；试解过了、中途某段解码失败的报错退出，不写半成品。视频结尾（按视频流算，音轨更长时不算音轨尾巴）之后的行没有画面可取，保留近黑底板、阶段 4 打一行提示。没有要取色的生成底板时不找视频。源视频从字幕稿的 `FlowOCR Video` 找（见[字幕稿](#5-字幕稿阶段-3-写阶段-4-读)的字段一条），`--video` 优先；找不到当场报错，不静默退回近黑底板。
  依据和开销见 [defaults.md 的底板取色一节](defaults.md#161-叠加底板取画面背景色plate_color默认关2026-10-22-定默认开2026-10-31-owner-改回默认关)。
* 不动的事件一段；**会动的按轨迹逐段**（停顿 `\pos` / 位移 `\move`，裁剪处端点插值），底板、正文、编号一起挪——
  一条从首点到末点的 `\move` 会把停顿和步进抹成匀速滑。Actor（Name 字段）是区域号 `r<n>`。
* **译文怎么分行**（owner 2026-11-09：叠加要还原目标语言版游戏实际显示的样子；`script.wrap_lines`）：照剧本里写死的换行分，去掉空行（剧本末尾多一个 `\N` 的就是一行）；
  匹配器的文本框画像给了"一行能放几个全角字"（这款游戏有自动折行的证据时才有）的，一行宽过它才折——按全角 1、半角 0.5 量宽，尽量往后断，
  句读不放行首、左括号不放行尾，拉丁文只在空格处断，占位标记和 Ruby 的正文当一个字不拆；断点按游戏的字数定，和叠加画多大字号无关。
  不按原文行框数凑行数（2026-10-05 起那种按原文各行框宽度比例重切的做法会把词切开：《魔裁》f1–f5 中文一行被切成两行的 127 条里 108 条切在词中间）。
  SRT 不受影响，照旧出剧本原句、按剧本换行分行。
* **正文译文怎么摆行**（`layout.place_rows`，阶段 3 的预览位置和阶段 4 共用）：按匹配器给的原文整块（条目的日文每一行一个框，含没收进条目、匹配器补出的行）摆。
  译文 n 行、原文整块 k 行：n = k 时译文第 i 行摆在原文第 i 行的框上；n ≠ k 时按行距排出 n 行，整块按文本框的竖直对齐（`valign`：上 / 下 / 居中）
  对齐原文整块的上沿 / 下沿 / 中心（按下沿量，Ruby 会把上沿撑高），横向取原文几行合起来的范围，出画面就整块往里推。
  共用锚轴只按原文整块里真实的框算（匹配器合成的行不算）。底板盖住原文整块 ∪ 译文各行：`rows` 方案拼成不重叠的横条（没有译文的原文行也盖上），
  `box` 一整块，`src` 只盖原文各行，`text` 照定义只盖译文。选项、名牌、tracks 的原文不走这里：正文比原文框多出几行时按原来一行的高度扩出几行、逐行画。
  matched 没有文本框画像（`overlay.textbox`）或正文条目没有原文整块（`block`）的，出叠加时当场报错、提示重跑匹配，不退回按 OCR 行框摆；SRT 照常出。
* **正文译文的字号与横向**（owner 2026-11-09，`layout.body_size`）：一个全角字和原文的一字宽（画像的 `em`）一样宽；译文行比原文宽时顺着对齐方向往外画
  （左对齐往右、右对齐往左、居中两边各一半），底板跟着放宽，上限是文本框宽（画像的 `box_w`，没有就是画面宽减边距）；最宽那行超过上限就整条缩到放得下，
  不设下面那条 75% 的保底；一条里各行同一个字号。没有 `em` 时按原文框适配（下一段）。

**底板按字实际落在哪里算**（2026-10-05）：libass 按字格（步进宽）对齐排字，墨迹在字格里不一定居中（「。」的墨迹在左半边），
只按墨迹宽、以锚点为中心算底板时，「疑」开头、「。」结尾的居中行墨迹比算的偏左十几像素、冲出底板。量字宽时另量每行左右留白
（左对齐、右对齐各渲一遍，`export.ink_side`；量字宽的 ffmpeg 次数因此翻倍，几百行仍是一两秒），底板和跟着字长的译文按"锚点 + 留白差"算，字的位置不动。
竖直方向同理：正文比原文框高（字号保底、或两个隔得远的原文框被当成一句的两行而按合起来的高定字号）时，底板按字形高（字号 / 1.35）以行中心往上下长；
libass 竖直居中时微软雅黑的墨迹比锚点低 0.04 个字号，逐行摆的字（阶段 4，和字幕稿的预览位置）锚点往上挪这么多（`export.ink_dy`），墨迹中心落在行中心上、上下留的底板一样宽（2026-11-10 owner 看图指出字贴着底板下沿）；
`box` 方案也把译文的左右范围并进来。底板四条边各自取整再画，上下相邻的两块之间不留缝。
底板比原文框和正文各外扩 2 px + 0.05 × 这一条的字号（`layout.plate_pad`，[defaults.md 1.77](defaults.md#177-底板边距按字号2-px--005-个字宽2026-11-10-owner-定)）；字幕稿的预览框逐行用行首的 `\bord` 写同一个值（预览框是 libass 围着行框画的，字往上挪了，它也比成品的底板高 1–2 px，只是示意）；
字离画面边的最小距离另是 `layout.EDGE_PAD`（6 px，没动），所以贴满整屏的长译文字号不受影响。

**字号换算是量出来的**（一次性探针 `probe_ass_fontsize.py`，libass 渲已知字号、量白色字形高）：
叠加 ASS 只用 Microsoft YaHei，ratio = Fontsize / 字形高 = **1.35**（CJK 正文）。同一个 Fontsize 换字体能差两成，
换字体要重跑探针。⚠ 字体名必须是这台机器上真有的：写一个不存在的，libass 会**静默换替身**，比例当场作废。

**框宽也给字号设上限**（2026-09-12，owner 看预览时指出只按框高定、字会冲出框）：
每行文本先在参考字号下**用 libass 真渲一次**、量墨迹宽（`export.ink_widths`，一页两次 ffmpeg（左对齐、右对齐各一遍，量左右留白）），
墨迹宽和字号成正比，于是 `Fontsize = min(框高 × ratio, 框宽 / 字号 1 的墨迹宽)`。
不拿字体文件的度量估：标定时 Yu Mincho 系统性偏 17%、Consolas 渲日文回退到别的字体后 −15%～+40%。
选项、名牌的译文另有保底（不低于框高换算的 75%，选项按钮的译文被压得过小那次加的），同栏同时在屏的选项取同一个字号；原文不保底，框偏高时保底会把字撑出框。
正文译文有原文一字宽时不走这里（见上面的字号与横向一条）。
核对（一次性探针 `probe_ass_fit.py`，按定好的字号再渲一遍量落没落在框里；2026-09-24 用 YaHei 重量）：
quick 的 q-gi-s2 全部 140 条事件墨迹宽 / 框宽 P50 0.69、最大 1.00；q-hsr-s2 抽 600 条 P50 0.97、最大 1.04，
超出 2% 的 9 条都是 1–3 个字的短框（`企`、`艾光`、`36m`）。

* **阶段 3 的 `default_srt` 写 `<base>-default.srt`**（tracks 的 base 是 `<tag>`，matched 是 `<tag>-<lang>`；`--opt keep=all`——matched 是 `show` 里含 `all`——时是 `-default_all`），不用 `<tag>-main.srt`：那是阶段 2 主轨 SRT 的名字，同名渲到建轨目录会把它悄悄换掉，而量具读的正是它（cue-shape 计划）。

## 5. 字幕稿（阶段 3 写，阶段 4 读）

字幕稿是一份普通的 ASS（`*.script.ass`），在 Aegisub、mpv 里直接打开就能看到大致效果：位置、淡入淡出、一个预览用的底框（自动的打字机只在阶段 4 的最终 ASS 里有，人手写的 `\k` 族 tag 预览里也看得到）。
人在这里改文字、时间、位置、打字机节奏；阶段 4 只读这份文件，不回读阶段 2，所以一份字幕稿就能交给译者、校对。
Aegisub 里的修改**不回流**到阶段 2 产物（owner 2026-09-27：先单向）。

**两类行**（结构照 Aegisub 卡拉OK模板的做法，标记用自己的——kara-templater 删**所有** Effect 为 `fx` 的行，借它的标记会互删）：

| 行 | 样子 | 谁写 |
| --- | --- | --- |
| 源行 | `Dialogue:`、Effect 是阶段 3 写的参数 `fo:…`（手补的行 Effect 为空）；阶段 4 处理过之后改成 `Comment:`、Effect 前面加 `fo-src\|` | 阶段 3，人编辑 |
| 生成行 | `Dialogue:`、Effect `fo-fx`（底板是 `fo-fx\|plate`）、样式是派生的 `<Style>.fo-fx` | 阶段 4 |

* **底板的标**：阶段 4 自己画的底板行（连同底板取色换成的小格）Effect 是 `fo-fx|plate`。下游要认出底板（比如把底板盖住的原文修补掉）只认这个标，不按长相认：
  扩展效果画的框也是 `\p1` 绘图，Effect 仍是 `fo-fx`（扩展效果把元素种类写成 plate 也一样）。
* **阶段 4 可以反复重跑**：先 `restore`（删 `fo-fx` / `fo-fx|…` 行和派生样式、把 `fo-src|` 行恢复成源行、去掉前缀，得到逐字节相同的字幕稿）再生成，
  所以阶段 4 的输出也是合法输入；`python -m flowocr.typeset x.ass --restore` 单独还原（`x.script.ass` 已经在就不覆盖——它可能是改过的，
  要覆盖加 `--force`，或 `-o` 另写一份）。提示里的行号是输入的那份文件的行号。
* **不碰的行**：用户自己注释掉的行（没有 `fo-src|` 前缀，带不带 `fo:` 参数都一样）、Effect 列有别的值的行（别人的 `fx`、`Banner;`…）原样留着、不生成。
* **字段**：Style 按角色（`Body` `Extra` `Name` `Title` `PlainName` `StrayName` `Choice` `Offmain` `Panel` `UI` `Special`，Style 表示"这是什么"；`Title` 是名牌下面字小一号的称号，`StrayName` 是长得像名牌、但不是挂在台词上又认出了译名的字——匹配器的 `stray_name` 组、退回画 OCR 原文的名牌、只有 tracks 时正下方没有主轨句子的名牌；匹配器判过名牌字色时 `Name` / `Title` 的主色是这款游戏的名牌色，原文字色对不上的名牌和称号用 `PlainName`（白字）；四种名牌样式阶段 4 都按名牌排，主色不是默认白的样式底板取色不改它的字色；`Special` 是匹配器 `special` 组（`matchedio.SPECIAL`：特殊上屏形式的台词与提示）的条目，不论哪一层都用它，阶段 4 按正文行排）；Actor 是区域号 `r<n>`（在不在主轨另由 `fo` 的 `off` 记）；
  Effect 是阶段 4 的参数；`[Script Info]` 里 `FlowOCR Video`（源视频，阶段 3 照产物 provenance 的 `video` 抄、数据目录下是相对路径；阶段 4 [底板取色](#4-导出)读它）、`FlowOCR Script`（格式版本）、`FlowOCR Source`（来自哪份产物，带 tracks `events[]` 的内容指纹 `events-sha256:…`——`ev` 是它的下标，
  指纹对不上的产物不能按 `ev` 回去）、`FlowOCR Code`（代码版本）只作追溯——写成键，Aegisub 会丢掉 `;` 注释行。
  派生样式名是 `<Style>.fo-fx`，底板取色的小格另用 `P.fo-fx`（`restore` 按这个后缀删，用户自己起的 `Sign.fx` 之类不受影响）；阶段 4 在 `FlowOCR Typeset` 里记外观和选项（取色时带 `plate_color=<算法版本>`），`restore` 一并删掉。
* **占位**（owner 2026-10-05）：剧本里的占位（`{NICKNAME}` 这类，见[一级产物只有一份](#1-一级产物只有一份)的占位一条）在正文里写成 `` [`编号:值] ``，
  值是匹配器猜的（没猜出来就空着，`` [`1:] ``）；编号按这份字幕稿里出现的先后分，`[Script Info]` 里 `FlowOCR Placeholder <编号>: <原来的占位> <值从哪来>` 是图例。
  用方括号加反引号，是因为 Aegisub 用的 VSFilter 不认花括号的转义，这种写法各渲染器都照原样显示；三款游戏的全部文本里 `` [` `` 出现 0 次。
  值里的半角方括号换成全角（最终也是全角）。阶段 4 把图例里有的标记换成值，值是空的就删掉、连带收拾落单的标点；
  要改就改标记里的值，或把整个标记换成文字（换掉了阶段 4 就不再碰）。断行按值的长度算，标记不拆到两行。
* **Ruby**（owner 2026-10-23，`ruby=on` 默认）：剧本的 Ruby 在正文里写成两个单独的注释块 `{ruby:读音}正文{/ruby}`——花括号里没有 `\`，渲染器不画（预览只见正文），
  Aegisub 里可以隐藏；不和样式的 tag 块合并。读音里会打断注释或被当成 tag 的 `{` `}` `\` 换成全角，读音里的占位照样写成 `` [`编号:值] ``。
  改正文时标记跟着字走；删掉两个标记就是不要这处 Ruby。读音里的占位换空了，这处标记去掉、正文留着。
  **阶段 4 把它画在正文上方**：每处一条单独的小字（`\an2`，和正文同一种元素，最终 ASS 的正文里不再有标记）——横向以正文那几个字的墨迹中心为中心
  （行左沿 + 墨迹宽(前缀+正文) − 墨迹宽(正文) / 2，量字宽时一起量；超出画面往里推），底边在这一行字形顶往上字号的 0.08 倍；
  字号是这一行的一半，比这一行正文宽就缩到放得下、不小于 0.3 倍，再放不下就两边伸出去。字色、粗体跟着正文那几个字（行首的字色 tag、正文开头处生效的样式块；
  底板取色改深 / 白字时一起改），淡入淡出、按轨迹分段、打字机（正文第一个字出现时整段出现，`dim` 时跟着半透明）都跟着这一行。
  底板往上并进读音（逐行的并进这一行那块，下一行的读音落在上一行那块里时不再叠一层；`box` 并进整块）；跟着字长的底板在读音出现时一下长到读音的右沿。
  一处 Ruby 跨了行（人在范围里加了换行）只画在开头那一行、盖到行尾；标记不是状态，按原框逐行摆时不补到下一行开头、不当行首块。
  整块画（一个框画几行、人挪过位置）的按 `\pos` 的锚点竖直等分各行；整块画在 `\move` 上的、阅读面板不画（打提示 / 面板按纯文字重新折行）。
  行内 `\fs` 改过的字宽不计（前缀和正文按这一行的字号量）。
* **一行的样子**：Effect `fo:ev=56 57;box=374 891 1588 931|…;fit=tr;rows;plate;tw=1750;was=…`，
  正文 `{\an5\pos(966,930)\fs52\fad(0,66)}正文第一行\N正文第二行`——正文里一个主流 tag 块 + 文字，
  **正文尽量是纯文字**（owner 2026-09-27：可以按需插 tag，但尽量避免、要便于编辑），参数都在 Effect 里、改字碰不到。
* **主流 tag**：`\an4/5/6` + `\pos`、`\fs`、`\fad`；在动的写一个首点到末点的 `\move` 供预览；多行（matched 的一个条目、tracks 的一条 cue）一条 Dialogue、行间 `\N`。
  样式 `BorderStyle=3` 出预览底框。打字机不写进正文，记成 `fo` 的 `tw`（字幕稿预览里没有打字机，最终 ASS 有）；
  要自己调某一行的节奏就在那一行写 `\k` 族 tag，阶段 4 按人写的节奏、不用 `tw`（样式的次要色全透明、阴影 0，预览也是逐字显出——`\ko` 藏不住阴影）。

**Effect 字段里的 `fo:…`**（owner 2026-09-27 提的）：主流 tag 表达不了的参数放 Effect 字段——它是 ASS 的标准字段，各编辑器原样保留，
Aegisub 里是单独一栏；渲染器只认 `Banner;` / `Scroll up;` / `Scroll down;` 开头的值，`fo:` 开头的忽略（libass 真渲核过：逐像素相同）。
不用 Aegisub 自己的 extradata：别的编辑器不认，保存时可能丢。
`fo:` 可以跟在别的内容后面（`备注;fo:…`、`Banner;10;fo:…`，libass 照样认前面的 Banner），它之后到末尾都是参数；
前面那段只留在源行上、不带到生成行——横幅 / 滚动这类渲染器效果在最终 ASS 里不生效，卡拉OK模板也不该往这些行上套。
项之间 `;`，每项 `名字` 或 `名字=值`；数值列表用空格分隔；值里的 `%` `;` `,` `{` `}` `\` 和换行按百分号编码——
Effect 不是 ASS 行的最后一个字段，逗号会把字段切错（Aegisub 保存时也会把它换成分号）。

正文译文（样式按正文排、`fit=tr`）不论行数和 `box` 对不对得上，都按原文整块摆行（`va` / `pitch`，见[导出](#4-导出)的摆行一条），人在字幕稿里改了行数也一样。
别的行（tracks 的原文、名牌、选项）：正文行数比原文框装得下的多（`cap`，默认就是框数）时，按原来一行的高度（几个框时取行距）往下扩出多的那几行、逐行摆，
往下会出画面就往上扩，压到别的字不管（owner 2026-09-27）；一个框本来装着几行（`cap` 比框数多）时，这个框按一行的高度（框高 / `cap`）长出去。
扩出的行只改排版，在动的行照原文框的轨迹走。几个框、其中有的框装着几行，这种再加行时不扩，整块画在 `\pos` 并打提示。
正文行数比原文框装的少时整块画在 `\pos`，字号按原来一行的高度适配。
底板按画出来的字宽：行内 `\fs` 改过字号的那几个字按它的字号量。Effect 为空的源行（手补的）照主流 tag 原样生成一条，只换派生样式。
不认识的 `fo` 参数**当场报错**、列出行号（`--opt unknown=ignore` 才跳过）。

**阶段 4 的顺序固定**，面板和普通条目走同一条路：排版（`wrap` 分行 → `fit` 定字号 → `rows` 定锚点 → 量文字边界）→ 元素（底板、正文、编号）→
运动（所有元素一起按 `path` 逐段展开）→ 时间效果（逐字 `\alpha`、`\fad`、配色）→ 全部行生成完之后底板取色（`plate_color=on`，只改生成行）。时间效果按**源行**的时间算：
在动的行拆成几段时，淡入淡出换成各段的七参数 `\fade`、逐字显出和人写的 `\t` / `\fade` 减去这一段的起点，段接段连起来和一整条相同，
不在每段从头放一遍；这一段开始前已经变完的 `\t` 换成里面的 tag 本身（libass 把结束时刻 0 读成到行尾，不能减成 0）。
扩展效果的 `tags` 挂点在每一段定稿之后调。
扩展效果（`--fx <模块>`，`flowocr.extensions` 的 `fx` 种类）有两个挂点：第 2 步加元素、第 4 步改元素的 tag；
模块声明 `NAME`（它在 `fo` 里的参数名），源行带了这个参数才调它。例子 `examples/fx_minimal.py`。
打字机行的底板跟着字长时，逐行摆的一行可能切成左右两块底板，`tags` 挂点在这一行的底板上会被调两次（每块一次）。

* **只在 libass 上核过**：字幕稿和最终 ASS 的效果（逐字显出、底板、淡入淡出）是拿 ffmpeg 的 `subtitles` 滤镜（libass）核的；VSFilter 系播放器（MPC-HC 等）没核。
* **不自造 `\xxx` 形式的 tag**：libass 按前缀认 tag，自造的名字容易被认成已有的（`\p` 开头的会被当成绘图模式开关）。预览底框用 `BorderStyle=3`、不用 4：4 只有 libass 认（script-fx 计划）。
